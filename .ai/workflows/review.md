# Technical Review Workflow

1. Read `AGENTS.md`, relevant architecture/conventions, and the requested change scope.
2. Do not modify files unless explicitly asked.
3. Review bugs, edge cases, maintainability, architecture, security, reliability, observability, cost, performance, readability, duplication, dependencies, configuration, and convention adherence as applicable.
4. Report evidence-based findings in priority order: Critical, High, Medium, Low, Improvement.
5. Cite relevant files and propose specific corrections. Avoid cosmetic suggestions without meaningful impact.
